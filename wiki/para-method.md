# PARA Method

An organizational framework for digital information by [[tiago-forte]], structured around four top-level categories: Projects, Areas, Resources, Archives.

## The four categories

- **Projects** — short-term efforts with a clear goal and end point (e.g., "redesign homepage," "write research report").
- **Areas** — ongoing responsibilities with no end date (e.g., "Marketing," "Health," "Finance").
- **Resources** — topics of interest for future reference (e.g., "graphic design," "personal productivity").
- **Archives** — inactive items from the above three categories, retained for reference.

## Key principle

Organize information by *where it is going* (the project or goal it serves), not by where it came from (subject or source). This is what Forte calls "organizing by actionability."

The most common mistake: confusing areas for projects. "Hiring" is an area; "fill three engineering positions by Q3" is a project. Without discrete projects, there is no sense of progress, no victories to celebrate, and motivation erodes.

## Relation to LLM Wiki

PARA provides a folder-level structure; the [[llm-wiki-pattern]] provides the maintenance layer. [[eric-j-ma]] notes his system was "inspired in part by Thiago Forte's numbered folder system" and documents it in an `AGENTS.md` so AI coding agents understand the vault structure.

Some practitioners (e.g., the Hackernoon author) use domain-specific vaults rather than one catch-all vault, which echoes PARA's "Areas" concept.
